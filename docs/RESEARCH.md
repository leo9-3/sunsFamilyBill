# 调研选型：家庭记账系统 + 微信服务号记账

日期：2026-11-17　需求（kalo 定）：

1. 账本服务端和数据都运行在 Muse 办公机上（数据不出本机）；
2. 家人关注微信服务号后，在手机上对服务号发一条消息就能记账；
3. 记账内容就三样：**年月日、事项、花销多少钱**。

## 一、现成开源记账系统对比

| 系统 | 许可证 | 技术栈 / 部署 | 多人/家庭 | 微信服务号发消息记账 | 结论 |
|---|---|---|---|---|---|
| **ezBookkeeping**（mayswind） | MIT | Go 单文件 + SQLite/MySQL，Docker 一条命令；带手机 PWA、报表、多币种，可导入微信支付/支付宝账单 | 多用户，但每人账本相互独立，不是“全家共用一本账” | ❌ 无公众号入口；有 API / MCP，可外挂桥接 | 最好的“完整账本”备选：轻、中文、维护活跃（约 6.1k star）。若以后想要正经网页报表，可由本项目把数据同步/导入过去 |
| **Firefly III** | AGPL-3.0 | PHP + MariaDB，Docker 组合较重 | 多用户，但每个人的账目（administration）互不共享，全家共用只能共用一个账号 | ❌ 无；有完整 REST API 可桥接 | 功能最强（复式记账、预算、规则），但对“发消息记三样东西”的需求明显过重，部署和维护成本高 |
| **Actual Budget** | MIT | Node，信封预算 | 多用户同步 | ❌ | 预算导向，不是流水账导向，且无中文/微信生态，不选 |
| **Beancount** | GPL | 纯文本复式记账 | 靠文件共享 | ❌ | 极客向，家人无法直接用，不选 |

**关键结论：没有任何一个成熟开源记账系统自带“微信服务号发消息记账”。**
市面上的微信记账玩法基本都是二次开发桥接（例如把 ezBookkeeping 当账本、再写一个微信消息桥调用它的 API），桥本身都要自己写。所以选型分两层：

- **记账入口层（本次自研，极小）**：本项目 `sunsFamilyBill` —— 零依赖 Node 服务 + SQLite 单文件库，只做三件事：收微信消息、按“日期 事项 金额”解析、存账并回复确认/汇总。代码量小、可审计、数据文件就一个 `data/family.db`，完全跑在 Muse 办公机上，符合 kalo 对纪要本验证过的偏好（零依赖、本地 SQLite）。
- **完整账本层（可选，第二期）**：若以后想要分类报表、多账户、预算，再引入 ezBookkeeping（MIT、Go 单文件、同样可跑本机），本项目通过其 API 或 CSV 导出对接；第一期不引入，避免为了用不上的功能先背上一个大系统。

## 二、微信服务号对接方式（官方通道）

只走官方通道，不用个人微信 Hook/协议登录（有封号风险，且那是个人微信不是服务号）。

- 家人关注服务号 → 在对话里发文字 → 微信服务器把消息以 XML **POST 到开发者配置的回调 URL** → 本服务验签（Token 做 SHA1 校验）、解析、记账 → 在 5 秒内以 XML **被动回复**一条确认消息。这是服务号/公众号都支持的基础能力，未认证账号也能用被动回复；认证服务号另有“客服消息”接口（48 小时内可主动发），第一期不需要。
- 服务号凭据：AppID、AppSecret（仅主动调用接口时需要）、**Token（开发者自己定，3–32 字符，两边填一致）**、EncodingAESKey（安全模式才需要；第一期先用明文模式跑通，再切安全模式）。
- 配置入口（2025-12 起迁移）：微信开发者平台 → 我的业务 → 公众号 → 消息与事件推送，填 URL / Token / EncodingAESKey。

## 三、硬约束：回调 URL 必须公网可达（80/443，不能带自定义端口）

微信服务器在公网，它只会往一个公网 http(80)/https(443) 地址推送消息，**到不了 Muse 办公机的 localhost**。这和“服务端和数据跑在 Muse 办公机上”不冲突，解法是加一条**入站隧道**：

- **推荐：Cloudflare Tunnel（cloudflared）** —— 在办公机上主动向外建一条隧道，得到一个 `https://<名字>.trycloudflare.com`（快速隧道）或自有域名（正式隧道）的公网 HTTPS 地址，微信把消息发到这个地址，隧道只把请求转发进本机服务。**账本程序和数据库始终在本机，隧道不存数据，只是邮递员。**
- 备选：frp（需要自己另有一台公网服务器做 frps）、nZucchini（免费版地址会变，服务号后台要跟着改，不适合长期）。
- 注意：Muse 办公机重启/隧道断开期间，家人发的消息微信不会补投（被动回复通道没有离线队列），所以隧道要做成开机自启并保活；这点已写进部署文档。

## 四、本项目第一期范围

- ✅ 微信消息记账：`2026-11-17 打车 35`、`11月17日 午饭 28`、`昨天 停车 10`、`打车 35`（默认今天）
- ✅ 微信内查询：`本月`、`今天`、`查 2026-11`；纠错：`删除上一笔`；`帮助`
- ✅ 收入顺带支持：`收入 2026-11-15 工资 12000`（或事项含“工资/到账”自动识别）
- ✅ 网页账本（同一服务）：按月看账、汇总、一句话补录、删错账 —— 数据同样在本机
- ✅ 家庭成员：按 openid 记“谁记的账”，可配成员名字映射和白名单（只有家里人能记）
- ⏳ 第二期候选：分类统计、月度报表导出 CSV、安全模式（EncodingAESKey 加解密）、对接 ezBookkeeping、Cloudflare 正式隧道（自有域名）
